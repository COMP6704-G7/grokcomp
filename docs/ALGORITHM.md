# Lion 算法笔记

本实验比较标准 Lion 与固定 AdamW 基线，不启用 Grokfast 梯度滤波。

设参数为 θ，当前梯度为 g，上一时刻动量为 m（初始为 0），学习率为 η，权重衰减为 λ：

1. 方向：u = sign(β₁m + (1−β₁)g)。
2. 参数：θ ← (1−ηλ)θ − ηu。
3. 动量：m ← β₂m + (1−β₂)g。

方向必须使用旧动量；计算方向不能提前覆盖动量。sign(0)=0。β₁控制当前方向，β₂控制历史记忆。衰减与梯度更新解耦；没有梯度的参数跳过更新与衰减。

实现位于 `lion_experiment/optim.py`。只保存一个与参数同形状的 `exp_avg`；支持参数组、closure 和 state_dict。对稀疏梯度和复数参数明确报错。

若参数数量为 P，Lion 和 AdamW 每步更新复杂度均为 O(P)。FP32 下 Lion 持久动量约占 4P 字节，AdamW 的一阶与二阶动量约占 8P 字节（另有各参数张量的 step 标量）。这不代表整个训练显存减半：模型、梯度、激活和临时张量仍需显存。这里的 Lion 方向表达式还会分配临时张量；总峰值以实测为准。

主配置为 Lion β=(0.9,0.99)，AdamW β=(0.9,0.98)，后者沿用组内原脚本的设置说明。两种算法的动量参数不同是预先规定的算法配置，不根据正式 seed 的表现修改。

学习率候选为 1e−4、2e−4、3e−4；Lion λ=5，因此 ηλ 分别为 0.0005、0.001、0.0015。AdamW η=0.001、λ=1，ηλ=0.001。只有中间候选与 AdamW 有相同峰值每步收缩强度，不能声称所有候选的正则强度都相同。

官方建议 Lion 学习率通常取 AdamW 的 1/3 到 1/10，衰减相应提高。该建议是调参起点，并不保证本任务上的性能优势。

验证使用 `vendor/lion_official.py` 中下载的 Google 官方实现：在 FP32、FP64 下给予相同参数、40 步梯度序列、零梯度、缺失梯度以及不同参数组，逐步要求参数和动量完全相等（rtol=atol=0）。来源、获取日期与 SHA-256 保存在同目录 provenance 文件；官方代码保持原版权和 Apache-2.0 许可证。

参考：[算法论文](https://arxiv.org/abs/2302.06675)、[官方实现](https://github.com/google/automl/blob/master/lion/lion_pytorch.py)、[调参说明](https://github.com/google/automl/blob/master/lion/README.md)。
